# 🐕 人柴村（じんしばむら）〜RIKOU村のおはなし〜

**追手門学院大学 理工学部「コンピュータインタラクション」授業ワーク**

人狼ゲームをもとにした、ほのぼの推理ゲームの授業用教材です。
ものづくりと科学が好きな人たちの村「RIKOU村」に、人に化けた柴犬たちがまぎれこみました。村人たちは話し合いで柴犬を見つけ出します。
人間同士、エージェント同士、そして**人間とエージェントの混在**で対戦できます。GitHub Pages と Google スプレッドシートだけで動きます。

### 役職（ゲームの仕組みは人狼と同じ）

| 人柴村での名前 | 人狼ゲームでの名前 | API・プログラム上の名前 | チーム |
|---|---|---|---|
| 柴犬 | 人狼 | `WEREWOLF` | 柴犬チーム |
| 柴推し | 狂人 | `POSSESSED` | 柴犬チーム |
| 占い師 | 占い師 | `SEER` | 村人チーム |
| 霊媒師 | 霊媒師 | `MEDIUM` | 村人チーム |
| 騎士 | 騎士（狩人） | `BODYGUARD` | 村人チーム |
| 村人 | 村人 | `VILLAGER` | 村人チーム |

- 夜の「襲撃」は、柴犬が村人を「もふもふの国へ連れていく」と表現しています。投票による「追放」は「村を旅立つ」です。
- プログラム上の名前（`WEREWOLF` など）は人狼知能と同じなので、人狼エージェントの知識がそのまま使えます。
自前のサーバーは不要で、次の 2 つだけで動きます。

| 部品 | 置き場所 | 役割 |
|---|---|---|
| `index.html` + `assets/` | GitHub Pages | 人間がプレイ・観戦するブラウザ画面と画像 |
| `gas/Code.gs` | Google スプレッドシートの Apps Script | ゲーム進行役（サーバー）。状態・ログ・結果をシートに保存し、発話を GPT で分類 |
| `results.html` | GitHub Pages | 結果・分析ページ（グラフ、試合一覧、参加者ごとの発話） |
| `avatar.html` + `avatar.js` | GitHub Pages | アバター工房と、アバター描画の共通ライブラリ |
| `config.js` | GitHub Pages | Apps Script の URL を書いておく設定ファイル（1 行だけ） |
| `teacher.html` + `qr.js` | GitHub Pages | 先生の画面（受付・進行・結果発表）と、学生に見せる QR コードを作る小さなライブラリ |
| `agents/` | 学生の PC / Google Colab | Python のエージェント（ルールベース・LLM） |

```
 ブラウザ(index.html) ──┐
 Python エージェント ───┼── HTTPS(JSON) ──▶ Apps Script ウェブアプリ ──▶ スプレッドシート
 CPU(サーバー内) ───────┘                      (進行・判定)              rooms / log / results
```

- 5〜9 人の村に対応しています（6 人: 柴犬1・柴推し1・占い師・騎士・村人2／7 人: ＋霊媒師／8 人: 柴犬2・占い師・霊媒師・騎士・村人3／9 人: 柴犬2・柴推し1・占い師・霊媒師・騎士・村人3）。
- 昼は**発言ラウンド制**です。1 ラウンドに 1 人 1 回発言するかパス（Over）します。全員がパスしたら投票に進みます。
- 発言は**自然言語**と**構造化タグ**（CO・占い結果・投票宣言など）の両方を持てます。LLM エージェントは文章を、ルールベースのエージェントはタグを読めばよい作りです。
- 締め切りを過ぎると自動で次に進みます（未投票はランダム）。人数が足りなければ CPU で埋められます。

## 0. 授業での流れ（授業セッション）

```
 先生: teacher.html で「受付をはじめる」 ─▶ 画面に出る QR コード（またはリンク）を学生に見せる
 学生: ① なまえ（学籍番号・ニックネーム） → ② アバター（「べつの姿にする」を押すだけでも OK）
       → （AIモードなら ③ AIの性格） → エントリー → 「RIKOU村のおはなし」（初回だけ） → 待機所
 先生: 「村をつくってはじめる」 ─▶ 6〜9 人の村に自動で分かれて、全部の村で同時に試合開始
       → 全村が終わると、先生の画面で結果発表（GPT による各村の分析・ベストゲームのリプレイ）
       → 「もう一回」で村を組みなおして何試合でも。学生は自動で次の村へ入ります
```

- 学生がリンクを**先に**開いてしまっても大丈夫です。「先生の合図を待っています」の画面になり、先生が受付をはじめると自動でエントリー画面に変わります。
- 学生の画面に出るボタンは「あそびかた」と「音」だけです（村の一覧・分析ページ・サーバー設定は、授業中の学生には出しません）。
- ゲーム中にやることは、いつも画面の下のパネルに出ます。再読み込みしても、同じ村・待機所に戻ります。

| URL | 使う人 |
|---|---|
| `teacher.html?api=…` | 先生（教室の大画面に映す）。セッション作成・エントリー一覧・締め切り・進行・結果発表・リトライ |
| `index.html` | 学生（**人間モード・AIモード共通**）。リンクは毎回同じなので、LMS に貼っておけます。開いている授業は自動で見つかります |
| `index.html?free=1` | 自由ロビー（授業の外で村を自分で作る・エージェントの練習用） |

**学生の参加のしかたは、先生が決めます。** 先生の画面の上にある「学生の参加のしかた」で、次の 3 つを授業中いつでも切りかえられます（授業をはじめるときの初期値も選べます）。学生はモードを選びません。
- **⏸ 受付しない**：学生の画面は「先生の合図を待っています」のまま。新しいエントリーは受けつけず、試合も始められません。
- **🙋 人間モード**：学生は自分で話し合い・投票します。
- **🧠 AIモード**：学生はAIの性格と作戦を決めて、**AIサバイバル戦（勝ち抜き戦）** で戦わせます。待機所にいる学生には、AIの設定画面が自動で 1 回出ます（設定しなかった人のAIは、標準の性格で戦います）。
  優勝が決まると「🏆 AIを組みなおして、もう一度サバイバル戦」ボタンが出ます。学生は待機所の「AIの性格を変える」でAIを調整してから、全員でもう一度 1 回戦から戦えます。

**例: 人間村を 4 回 → AIサバイバル戦を 2 回**
1. 人間モードで「受付をはじめる」→「村をつくってはじめる」→ 結果発表の「🔁 もう一回」を 3 回。
2. 上の切りかえを「🧠 AIモード」にする（学生の画面にAIの設定が出るので、1〜2 分待つ）。
3. 「🏆 AIサバイバル戦をはじめる」→ 各回の「次の回へ」→ 優勝決定。
4. 「🏆 AIを組みなおして、もう一度サバイバル戦」（学生に、AIを見直す時間を 1〜2 分あげる）→ 優勝決定。
5. 「授業をおわる」。

切りかえは、次の試合から反映されます。

※ 先生の画面の QR コードは、押すと全画面に大きく映せます。QR もリンクも `index.html` だけです（`config.js` に Apps Script の URL を書いた場合）。

### 村の分け方
- オンラインの参加者を毎回シャッフルし、`ceil(人数÷9)` 個の村に均等に分けます（例: 23 人 → 8・8・7 人）。だれも外れません。
- 6 人に足りない村は CPU で埋めます。5 人以下でも試合ができます。
- **CPU の席には、情報工学科の先生（上野先生・駒谷先生・佐藤先生・寶珍先生・宮本先生・山口先生・辻先生・遅先生）が座ります。** 同じ村に同じ先生は 2 人出ません。先生ごとにイラストのアバターとプロフィールがあり、1 日目には先生らしいあいさつをします（ゲームの強さはふつうの CPU と同じです）。円卓で先生の席にマウスをのせると、全身のイラストとプロフィールが出ます。
- 先生の名簿は `gas/Code.gs` の `TEACHERS`、絵は `assets/teachers/<キー>.webp`（丸いアイコン）と `<キー>_full.webp`（全身）です。名簿を空にすると、これまでどおり「CPU1」などの名前になります。
- 待機室を閉じている（2 分以上通信がない）人は、その回の村分けから外れます。戻ってくれば次の回に入ります。

### 途中で抜けても大丈夫なしくみ
- 試合中に 25 秒以上通信がない人は「おるすばん（自動）」になり、CPU と同じロジックで代わりに行動します（画面に 💤）。戻ってくれば、すぐ自分で操作できます。
- 締め切りを過ぎると、未行動の人の分は自動で進みます。サーバーは学生・先生のだれかが画面を開いていれば進行します。
- 秒数はスクリプトプロパティ `AWAY_SEC`（既定 25）と `AWAY_GRACE_SEC`（試合開始直後の猶予、既定 40）で変えられます。

### 🎨 アバター工房の「図形でつくる」
- アバター工房（`avatar.html`）の上で「パーツでつくる／図形でつくる」を切りかえられます。
- 「図形でつくる」は、まる・たまご・おばけ・おもちの体に、耳（ねこ・うさぎ・くま・いぬ・つの・アンテナ・ふたば）、もよう（いぬの口もと・まろ眉・三毛・しましま・たぬき・ペンギン・パンダ目）、しっぽ、目、口、かざりを組み合わせる、まるい「いきもの」です。授業ワーク「アクセルロッドのコンテスト」のキャラ作成と同じ部品です。
- 「おすすめ」から赤柴・黒柴・白柴・三毛ねこ・たぬき・ペンギン・パンダ・おばけを選んで、そこから変えることもできます。すべて SVG なので画像は不要です。
- CPU のアバターも、2 割くらいがこの「いきもの」になります。

### 🏆 AIサバイバル戦（AIモードの勝ち抜き戦）
- 先生の画面の「AIサバイバル戦をはじめる」で、オンラインの AIモードの参加者だけで村をつくります。
- **勝ったチームで、最後まで生き残った AI** だけが次の回へ進みます。役は毎回ふり直し。勝ち上がりが 9 人以下になったら 1 つの村で決勝、決勝で勝ち残った AI が優勝です（6 人に足りない村は CPU で埋め、CPU は勝ち上がりに数えません）。
- AI だけの村は待ち時間を短くしています（発言 30 秒・2 ラウンド・投票と夜 20 秒が上限。全員が行動すればすぐ進む）。
- 先生の画面にトーナメント表と優勝者を表示します。脱落した人・人間モードの人の待機所には、いま戦っている村の「観戦」ボタンが出ます。

### AIモードとベイズ推定
- 学生は「論理性・感情・積極性・疑い深さ・協調性・大胆さ」を 0〜100 で設定し、基本戦略を文章で書きます（プリセット: 名探偵／ムードメーカー／慎重派／大胆不敵）。
- AI は毎フェーズ、**だれが柴犬かをベイズ推論風に見積もります**。事前確率（残りの柴犬の数 ÷ 生存者）から、占い結果・霊媒結果・投票先・発言の内容・沈黙などの証拠を、パラメータに応じた重みで対数オッズに足していきます（例: 論理性が高いと占い結果や投票の矛盾を重く、感情が高いと強い言葉や印象を重く見ます）。
- その確率と理由を LLM に渡し、性格と戦略に合わせて発言・投票・夜の行動を決めさせます。API キーがなければ同じ推定をもとにルールで行動します。
- 推定の過程は保存され、分析ページの試合詳細「🧠 AIの推理の過程」で、各プレイヤーの「柴犬である確率」の推移のグラフと理由として見られます（本当の柴犬の線が太いオレンジ）。AIモードの学生の画面にも、試合中にリアルタイムで表示されます。
- AI の行動は、AIモードの学生のブラウザが開いている間に動きます（閉じると「おるすばん」の CPU ロジックになります）。LLM の費用は先生の API キーにかかります（1 試合で AI 1 人あたり十数回の呼び出し）。

## 自分のパソコンで動作チェックする

- **最低 1 人から動きます。** 村が 6 人に足りないときは、先生 CPU が空いた席に座ります（1 人なら、自分＋先生 5 人）。AIサバイバル戦は、AIモードの学生が 2 人以上で始められます。
- **1 つのブラウザで何人分も参加できます。** 学生のリンクの後ろに `?as=1`、`?as=2`… を付けて、タブごとに開いてください（例: `index.html?as=1`）。番号ごとに別の学生として保存されます。シークレットウインドウは、ウインドウ同士で保存場所を共有するので、何枚開いても同じ学生になってしまいます。
- **人数を一気に増やすときは** `test/sim_students.py` を使います（Python が必要）。
  `JINRO_API=https://script.google.com/macros/s/…/exec python test/sim_students.py auto 5`
  （`auto` は「いま開いている授業に入る」。5 は人数）。人間モードの擬似学生はランダムに発言・投票します。AIモードでは本物の AI（OpenAI）を呼ぶので、API の料金がかかります。
- Apps Script は同時アクセスに上限があるので、擬似学生は 5〜8 人くらいまでにしておくのが無難です。

## リプレイのシアター上映（声・音楽つき）

結果発表の「▶ みんなで観る」や「▶ リプレイを見る」を押すと、試合を**映画のように上映**します（`index.html?replay=試合ID`）。

- 登場人物が円卓にならび、話している人にスポットライトが当たって、字幕が声に合わせて出ます。
- 「占い師 CO！」「柴犬判定！」などの大事な発言には、大きな見出しが入ります（神視点では「じつは、うそ」も出ます）。
- 投票は、だれがだれに入れたかを線と票の玉で 1 本ずつ見せます。夜の出来事・朝・勝敗は実況が読み上げます。
- 場面（昼・投票・夜・おわり）ごとに、音楽が変わります（その場で音を作るので、音源ファイルは要りません）。
- 操作: スペース = 再生／一時停止、→ = 次へ、← = ひとつ前へ、F = 全画面。下のバーで速さ・声・音楽・神視点を切りかえられます。

### 声（VOICEVOX）の準備

上映するパソコンで **VOICEVOX**（無料の読み上げソフト）を起動しておくと、登場人物ごとにちがう声で読み上げます。

1. VOICEVOX を起動します。
2. はじめて使うときだけ、ブラウザで `http://localhost:50021/setting` を開き、「Allow Origin」に GitHub Pages のアドレス（例: `https://<ユーザー名>.github.io`）を入れて保存し、VOICEVOX を起動しなおします。
3. リプレイを開くと、はじまりの画面に「🟢 VOICEVOX につながりました」と出ます。ブラウザが「ローカル ネットワークへのアクセス」をたずねてきたら、許可してください。

- VOICEVOX が見つからないときは、ブラウザの読み上げ（声は 1 種類で、高さだけ変えます）か、字幕だけで上映します。
- 使った声は、画面の右上とおわりの画面に「音声 VOICEVOX：キャラクター名」と表示します（VOICEVOX の利用規約で、クレジットの表示が必要です）。動画にして公開するときは、各キャラクターの利用規約も確かめてください。
- 声は上映のたびに、その場で作ります。CPU だけのパソコンでは 1 文に 1〜2 秒かかるので、次のせりふを先回りして作っています。

## 1. サーバー（スプレッドシート + Apps Script）の準備（教員・5 分）

1. Google ドライブで新しいスプレッドシートを作ります（大学の Google Workspace アカウントを推奨）。
2. メニュー「拡張機能」→「Apps Script」を開き、`gas/Code.gs` の中身を全部貼り付けて保存します。
3. 関数 `setup` を選んで「実行」し、権限を承認します。`rooms` / `log` / `results` シートができます。
4. 「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」を選びます。
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **全員**
5. 表示された URL（`https://script.google.com/macros/s/…/exec`）を控えておきます。これが **API URL** です。

> **Code.gs を修正したとき**は、「デプロイを管理」→ 鉛筆アイコン → バージョン「新バージョン」で更新してください。
> 「新しいデプロイ」を作ると URL が変わってしまいます。

## 2. 画面（GitHub Pages）の公開

1. このフォルダをそのまま GitHub リポジトリに push します。
2. リポジトリの Settings → Pages → Branch: `main` / `/ (root)` を選びます。
3. 学生には API URL を付けたリンクを配ります（URL エンコードしておくと安全です）。

```
https://<ユーザー名>.github.io/<リポジトリ名>/?api=https://script.google.com/macros/s/XXXX/exec
```

**おすすめ：** `config.js` の `window.JINRO_API = "";` の `""` の中に API URL を貼っておくと、`?api=` は要らなくなります。
`teacher.html`・`index.html`・`results.html` のどれにも効き、先生の画面の QR コードとリンクも短くなります（例: `https://<ユーザー名>.github.io/<リポジトリ名>/teacher.html` だけで開けます）。
`?api=` を付けて開いたときは、そちらが優先されます。

## 2.5 画像と演出

- 画面は、`assets/` に置いた画像（背景・村人のアイコン・役職カード・演出用の場面）を自動で使います。**画像が無くても、CSS で描いた代替表示で全部動きます。**
- 画像は ChatGPT に作ってもらう前提で、依頼文を [`docs/image_prompts.md`](docs/image_prompts.md) にまとめてあります（全 38 枚、ファイル名つき）。背景・円卓の広場・役職カード・場面の演出・勝敗画面・マスコット「ポチ」（雑種の犬）・村の紋章・スタンプなどです。
- できた画像は `assets_raw/` に入れて `python tools/optimize_images.py` を実行すると、WebP に縮小・変換して `assets/` に出力します。同時に、読み込む画像の一覧 `assets/manifest.json` も作ります。
- 演出の内容: 昼・夕・夜で背景と円卓の明るさが切り替わる、円卓に吹き出しが出る、役職カードをめくる、投票（投票した人の顔が 1 票ずつ並ぶ）、連れ去り・旅立ち・平和な朝の場面、勝敗発表（チームごとに全員の役職を公開）。
- 全画面の演出は「役職発表・投票の結果・朝のしらせ・勝敗」だけです。昼・投票・夜への切りかわりは、円卓を横切る帯で知らせるので、操作は止まりません。演出がたまったときは自動で早送りになります。
- 効果音は右上の「音」ボタンで ON/OFF できます（素材ファイルは不要で、ブラウザ内で合成しています）。自分の番が来たとき・残り 5 秒のときにも鳴ります。
- 画面共有するときは、役職カードをクリックすると裏返して隠せます。
- 演出は、画面をクリック（または Enter・スペース）すると次へ進みます。OS の「視差効果を減らす」設定が有効な場合は、アニメーションを短くします。

## 2.55 アバター工房（各自が自分のアバターをつくる）

`avatar.html`（エントリー画面の「🎨 じぶんで細かくつくる」、待機所の「アバターを変える」）で、自分だけのアバターを作れます。
エントリー画面の「🎲 べつの姿にする」を押すだけでも、その場でアバターが決まります（工房に行かなくてもエントリーできます）。
- 種族は、人間・柴犬・猫・うさぎ・きつね・お化け・精霊・ロボットから選べます。人外は毛色・からだの色も選べます。
- 組み合わせるパーツは、背景・服・顔・目・口・髪・帽子/髪飾り・眼鏡です。
- 人外にも服や帽子・眼鏡を着せられます（お化けと精霊は服を着ず、ふわふわの体のままです）。

- 「この姿に決める」を押すと、ブラウザに保存されます。村に参加したときに、全員の画面（円卓・会話ログ・投票結果・リプレイ・分析ページ）にそのアバターが出ます。
- 待機中・ゲーム中に工房で変えても、ゲーム画面に戻ると自動で反映されます。
- 「そのほか」→「画像（PNG）で保存」で画像として書き出せます（名札やスライドにも使えます）。
- アバターを作っていない人・エージェント・CPU は、名前から自動で作ったアバターになります（`assets/avatar_XX` の肖像画像があればそちらを使います）。
- Python のエージェントにもアバターを付けられます。工房で「決定」したアバターの JSON（ブラウザの `localStorage` の `jinro_avatar`）を、エージェントのクラスの `avatar = {...}` に貼ってください。

**パーツについて**
- 標準パーツ（SVG）は最初から入っていて、色を自由に選べます。季節の要素は入れず、汎用的なものにしています。
- 画像パーツは ChatGPT に作ってもらって追加できます。依頼書は [`docs/avatar_parts_prompts.md`](docs/avatar_parts_prompts.md)（人外の頭を含めて全 78 枚）です。素体テンプレートの `docs/avatar_template.png` を添付して頼みます。
- できた画像は `avatar_raw/` に入れて `python tools/avatar_parts.py` を実行します。次のことを自動で行います。
  - 背景を透明にする
  - 決まった位置と大きさにそろえる
  - WebP に変換して `assets/avatar/` に出力し、パーツ一覧 `manifest.json` を作る
  - 確認用の一覧画像 `avatar_raw/_preview.png` を作る
- 画像パーツは、工房の「色味を変える」スライダーで色を変えられます。

## 2.6 結果・分析ページとリプレイ

`results.html`（先生の画面の「📊 分析ページ」、自由ロビーの右上の「📊 分析」）で、終わった試合を振り返れます。

| タブ | 内容 |
|---|---|
| 概要 | 勝った人と負けた人の話し方の比較、その話し方を多く使った人の勝率、役職ごとの話し方（ヒートマップ）、人間・エージェント・CPU の話し方の違い |
| 試合 | 面白さスコア順の試合一覧（見どころバッジ付き）、試合ごとの詳細（全員の役職・夜の行動・発話の分類） |
| 参加者 | 学籍番号ごとのランキング（表示はいちばん新しいニックネーム。学籍番号そのものは画面に出ません）、個人の話し方の特徴（全体平均との比較）、役職別の成績、発話の一覧 |

- **話し方の分類**: 推論・挑発/圧力・推定・情報開示・感情表現・提案/誘導・質問・反論/弁明・その他 の 9 種類です。発言が本当か嘘かではなく、話し方・働きかけ方で分けます。
- **リプレイ**: 試合一覧の「▶ 演出付きリプレイ」（`index.html?replay=試合ID`）で、ゲーム本番と同じ演出で再生します。
  - 「神視点」を選ぶと、全員の役職と夜の行動（襲撃・占い・護衛）が見えます。オフにすると、参加者と同じ情報だけで推理しながら観られます。
  - 再生・一時停止、速さ（0.5〜4 倍）、日付ジャンプ、シークバーで操作します。
  - URL を共有すれば、誰でも同じリプレイを観られます。
- **面白さスコア**: 日数、対抗 CO、偽の黒出し、護衛成功、同票、最終日の接戦（崖っぷちの逆転）、騙りでの勝利、舌戦（挑発と反論が多い）などから計算します。

### GPT による分類の設定（教員・1 回だけ）

1. Code.gs を更新したら、関数 `setup` をもう一度実行し、外部サービスへの接続（UrlFetchApp）を許可します。続けて、ウェブアプリを「デプロイを管理」から新しいバージョンにします。
2. スプレッドシートを開き直すと、メニューに「🐕 人柴村」が出ます。「GPT の API キーを設定する」で次の値を入れます。
   - API キー（OpenAI のキー）
   - モデル名（使いたいモデル。OpenAI のモデル一覧から選んでください）
   - API の URL（OpenAI なら空欄。OpenAI 互換の別サービスを使うときだけ入力）
   - 「プロジェクトの設定 → スクリプト プロパティ」で、`OPENAI_API_KEY` `OPENAI_MODEL` `OPENAI_BASE_URL` を直接設定しても同じです。
3. 分類は、分析ページを開いたときに未分類の試合から自動で始まります。メニューの「自動分類（5 分ごと）を有効にする」を選ぶと、誰も開かなくても分類が進みます。

- **API キーが無い場合**は、キーワードによる簡易分類になります。分析ページ・リプレイは同じように使えます。
- **費用**: 1 試合あたり、発話をまとめて 1〜数回だけ API を呼びます。分類済みの試合は二度と送りません。
- **個人情報**: 発言の文章とプレイヤー名が OpenAI（設定した API）に送られます。授業で使う前に学生に伝えてください。名前の代わりにニックネームを使うのがおすすめです。
- **分類をやり直す**: メニューの「分類をやり直す」で、全試合が未分類に戻ります。モデルや定義を変えたときに使います。
- 分類結果は `utterances` シート（1 行 = 1 発話）に、試合の一覧とスコアは `games` シートに入ります。スプレッドシートで自由に分析できます。

## 3. 遊び方（人間）

授業では、上の「授業セッション」の流れを使います。ここは、授業の外で自由に遊ぶとき（`index.html?api=…&free=1`）の手順です。

1. 名前を入れ、「村をつくって入る」か、一覧から「入る」を押します。
2. 村を作った人は「ゲームを始める」を押せます（足りない席は CPU が座ります）。
3. 「友だちをよぶ」のリンク（`?room=…`）を送ると同じ村に直接入れます。参加していない人は観戦になり、役職はゲーム終了後に公開されます。

### ゲーム中の操作（授業セッションでも同じ）

- **昼**: 下のパネルに文章を書いて「発言する」（または「今回はパス」）。**ひとことボタン**（🔍 あやしい人を言う・🤝 信じる人を言う・⚖️ 投票先を言う・📣 役職を名乗る・🔮 占い結果を言う）を押して相手を選ぶと、文章と一緒に**構造化タグ**（`ESTIMATE` `VOTE` `CO` `DIVINED` など）が付き、エージェントにも伝わります。
- 占い師・霊媒師は、左の「あなただけが知っていること」の「発表する」を押すと、結果がそのまま発言欄に入ります。
- **投票・夜**: 下のパネルの名前か、円卓の顔を押して選びます。時間内なら選び直せます。
- 書きかけのままラウンドが終わっても、文章は次のラウンドに残ります。
- 右上の「📖 あそびかた」で、ルールと、その村にいる役職をいつでも確認できます。

## 5. API 仕様（どの言語からでも使えます）

授業セッション用の API（先生は `adminKey`、学生は `token` を付けます）:
`createSession` `currentSession` `entry` `sessionState` `updateSession` `startRound` `aiAct` `analyzeRound`。
スクリプトプロパティ: `OPENAI_API_KEY` `OPENAI_MODEL` `OPENAI_BASE_URL`（GPT 用）、`OPENAI_REASONING_EFFORT`（gpt-5 系で `minimal` にすると考える量が減って安く速くなる）、`TEACHER_CODE`（設定するとセッション作成にコードが必要）、`AWAY_SEC` `AWAY_GRACE_SEC`。


すべて `POST <API URL>` で、本文は JSON（`Content-Type: text/plain` で可）です。返答は `{"ok": true, ...}` または `{"ok": false, "error": "..."}` です。

| action | パラメータ | 返り値 |
|---|---|---|
| `listRooms` | – | `rooms` |
| `createRoom` | `name, size(5/9), talkSec, voteSec, nightSec, talkRounds` | `roomId, hostToken` |
| `join` | `roomId, name, kind("human"/"agent")` | `playerId, token` |
| `addCpu` | `roomId, hostToken, count` | – |
| `start` | `roomId, hostToken, fillCpu` | – |
| `state` | `roomId, token?, v?` | `state`（自分に見える情報のみ）。`v` が最新版と同じなら `unchanged: true` |
| `talk` | `roomId, token, text, tags[], skip?` | – |
| `vote` | `roomId, token, target` | – |
| `night` | `roomId, token, target` | – |
| `game` | `roomId` | 終了した試合の全データ（役職・夜の行動・発話の分類を含む。リプレイ用） |
| `results` | `fresh?` | 分析ページ用の集計（試合一覧と、プレイヤー × 試合ごとの発話カテゴリ数） |
| `playerUtterances` | `name` | ある名前の参加者の全発話 |
| `classify` | `max?` | 未分類の試合を分類する（同時に 1 つだけ実行されます） |
| `setAvatar` | `roomId, token, avatar` | 自分のアバターを変更（`join` にも `avatar` を付けられます） |

**タグ**（`tags` 配列の要素）

| type | 例 | 意味 |
|---|---|---|
| `CO` | `{"type":"CO","role":"SEER"}` | 役職のカミングアウト |
| `DIVINED` | `{"type":"DIVINED","target":3,"result":"WEREWOLF"}` | 占い結果の発表 |
| `IDENTIFIED` | `{"type":"IDENTIFIED","target":3,"result":"HUMAN"}` | 霊媒結果の発表 |
| `VOTE` | `{"type":"VOTE","target":2}` | 投票先の宣言 |
| `ESTIMATE` | `{"type":"ESTIMATE","target":4,"role":"WEREWOLF"}` | 推測 |
| `AGREE` / `DISAGREE` | `{"type":"AGREE","talkIdx":12}` | ある発言への賛成・反対 |

役職名: `WEREWOLF` `POSSESSED` `SEER` `MEDIUM` `BODYGUARD` `VILLAGER`

## 6. ルールの詳細

- 占い師は、ゲーム開始時点で「柴犬ではない誰か 1 人」の占い結果（人間）を持っています。
- 1 日目の夜から連れ去り（襲撃）があります。柴犬が複数いるときは多数決で、同数なら抽選です。
- 騎士の護衛先が襲撃されたら、誰も死にません（自分は護衛できません。連続護衛は可）。
- 投票が同数のときは抽選です（決選投票はありません）。
- 勝敗: 柴犬が 0 人なら村人チームの勝ち、柴犬の数が人間の数以上なら柴犬チームの勝ちです（柴推しは人間に数えますが柴犬チーム）。

## 7. データの分析

- `results` シート: 1 行 = 1 プレイヤー × 1 ゲームです。ピボットテーブルで「名前 × 役職 → 勝率」の表がすぐ作れます。
- `log` シート: 全発言（タグ付き）・投票・夜行動・処刑・襲撃の記録です。発言分析やエージェントの振り返りに使えます。

## 8. 制限と注意

- 通信がとぎれたとき・サーバーが混み合ったときは、画面の上に「つなぎ直しています…」と出て、自動でやり直します（エラーの連発や、画面の停止は起きません）。
- Apps Script は同時実行数に上限（1 ユーザーあたり 30 程度）があります。画面は 2 秒、エージェントも既定で 2 秒ごとに状態を確認します。40 人規模なら問題ない想定ですが、大人数で連戦するときは `--poll 3` などで間隔を広げてください。
- 1 回の処理に 0.3〜1 秒かかるため、リアルタイム性が必要なゲームには向きません（ラウンド制にしているのはこのためです）。
- `token` を知っていれば誰でもそのプレイヤーとして行動できます。授業用の簡易な仕組みです。
- 古い村は `rooms` シートに残ります。学期の区切りで行を削除してかまいません（`log` / `results` は残ります）。
