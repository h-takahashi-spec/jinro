# 人柴村 授業ガイド（例: 90 分 × 4 回）

**追手門学院大学 理工学部「コンピュータインタラクション」授業ワーク**

> 人柴村は人狼ゲームと同じ仕組みです（柴犬 = 人狼、柴推し = 狂人）。資料や論文で人狼知能を調べるときは、この対応で読み替えてください。

## ねらい
- 不完全情報・コミュニケーションゲームとしての人狼（人柴村）を体験し、「推論」「説得」「嘘」を言語化する。
- 人間の戦略をルールとして実装し、LLM を使ったエージェントとの違いを比較する。
- 対戦ログを分析し、エージェントを改良するサイクルを回す。

## 毎回の進め方（授業セッション）

1. 教室の大画面に `teacher.html` を映し、「受付をはじめる」を押す。画面に出る QR コード（押すと全画面に大きく映せます）かリンクを学生に見せる。AIモードの回は、QR の上の「🧠 AIモード」に切りかえる。
2. 学生は学籍番号・ニックネーム・アバターを登録してエントリー。おはなしを見たら待機所で待つ（待機所には「あそびかた」が出ています）。
3. 人数がそろったら「村をつくってはじめる」。6〜9 人の村に自動で分かれて試合開始。
4. 全村が終わると結果発表。GPT の分析を読み、ベストゲームを「みんなで観る」。
5. 「もう一回」で村を組みなおす。1 試合 10〜15 分なので、90 分で 3〜4 試合できます。

**AIモードを使う回のおすすめ**: 前半は全員人間モード、後半は半分の学生が AIモードで参加。終わったら分析ページの「AIの推理の過程」を見ながら、「どのパラメータの AI が柴犬を早く見抜いたか」「戦略の文章で行動がどう変わったか」を話し合います。

## 第 0 回（または第 1 回の冒頭 15 分）: アバターをつくる
- `avatar.html` で自分のアバターを作り、「この姿に決める」を押す（授業セッションでは、エントリー画面の「じぶんで細かくつくる」から行けます）。人間だけでなく、柴犬・猫・お化け・精霊・ロボットなども選べる。
- 「そのほか」→「画像（PNG）で保存」した画像を、自己紹介スライドや名札に使ってもよい。
- 余裕があれば、アバターに込めた「キャラ設定」（疑り深い、陽気、無口など）を一言書いておき、ゲーム中の話し方の目標にする。分析ページの「話し方の特徴」で、キャラ設定どおりに話せたかを振り返れる。

## 第 1 回: 人間同士で遊ぶ（人柴村を知る）
| 時間 | 内容 |
|---|---|
| 15 分 | ルール説明（役職・昼夜・勝利条件）、画面の使い方 |
| 50 分 | 5 人村を班ごとに 3〜4 ゲーム（発言 90 秒 × 3 ラウンド）。足りない席は CPU |
| 25 分 | 振り返り: 「何を根拠に投票したか」「占い師が 2 人出たらどうするか」を班で書き出す |

**ミニ課題**: 自分が使った判断ルールを「もし〜なら〜する」の形で 5 個書く。

## 第 2 回: ルールベースのエージェント
| 時間 | 内容 |
|---|---|
| 20 分 | `wolfclient.py` の `Game` クラスと、`talk / vote / night` の流れを解説 |
| 15 分 | `rule_agent.py` を読む（タグの読み方、CO 一覧、占い結果の集計） |
| 45 分 | 第 1 回のルールを `my_agent.py` に実装し、`run_agents.py --games 20` で勝率を見る |
| 10 分 | 勝率の発表 |

**課題**: RuleAgent に対する勝率を上げる。改良点と勝率の変化を記録する（20 戦以上）。

## 第 3 回: LLM エージェント
| 時間 | 内容 |
|---|---|
| 20 分 | `llm_agent.py` の解説: 状況の文章化（`summary_text`）、プロンプト、JSON 出力、失敗時の代行 |
| 50 分 | プロンプトや渡す情報を工夫する。人間 1 人 + LLM + ルールの混在村で遊んでみる |
| 20 分 | 議論: LLM はタグ（構造化情報）を正しく出せたか。嘘はうまいか、見抜けるか |

**課題**: ルールベースと LLM を組み合わせたハイブリッドエージェントを作る（例: 投票はルール、発言は LLM）。

## 第 4 回: 大会と分析
| 時間 | 内容 |
|---|---|
| 40 分 | 総当たり戦: 教員が `run_agents.py --agent team1:Team1Agent:1 --agent team2:...` で連戦する |
| 30 分 | `results` シートのピボットで役職別勝率を出し、`log` シートから印象的な場面を探す |
| 20 分 | 各班の発表（工夫した点・失敗した点） |

### 分析ページを使った振り返りの例
- 第 1 回の後に、自分の「話し方の特徴」（参加者タブ）を見て、次の試合で試す話し方を 1 つ決める。
- 「勝った人と負けた人の話し方」を陣営別に切り替えて、村人チームと柴犬チームで有利な話し方が違うかを議論する。
- 面白さスコア上位の試合を、神視点オフのリプレイで全員で観て、どこで柴犬に気づけたかを話し合う。
- 人間とエージェントの話し方の違い（概要タブの一番下）から、エージェントに足りないコミュニケーションを考え、`talk()` の改良につなげる。

## 評価の観点（例）
- 勝率（役職別・対 RuleAgent）
- 実装した戦略の説明の明確さ（なぜそのルールか）
- ログ分析に基づく改良のサイクル
- LLM とルールの長所・短所についての考察

## 運営のコツ
- 第 1 回は発言時間を長め（90〜120 秒）にし、エージェント戦は短く（20〜30 秒）します。
- 学生のエージェントは Colab から動かすと環境の差が出ません（`agents/colab_quickstart.ipynb`）。
- LLM の API キーは、Colab の「シークレット」機能に入れるよう指導します（ノートブックに直接書かない）。
- 連戦の前に、1 戦だけ `--talk-sec 10` で動作確認するとトラブルが減ります。
