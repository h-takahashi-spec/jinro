## 安定して動くようにしたところ

- 通信を同時に 2 本走らせない・古い返事は捨てる（状態が巻きもどる表示をなくした）
- 通信の失敗・サーバーの異常な返事では、エラーを連発せず、間隔をあけて自動でやり直す（画面上部に表示）
- 返事が来ないときは時間切れにして、やり直す（これまでは待ちつづけて止まることがあった）
- 発言・投票・エントリーのボタンは二度押しを防ぐ。投票は押した瞬間に表示へ反映する
- 書きかけの文章は、ラウンドが変わっても残る
- 再読み込みしても、同じ村・待機所に戻る（終わった村に入り直してしまう不具合を修正）
- 演出がたまったら早送りにして、話し合いの時間を食わない。村を移るときは演出を打ち切る
- タブに戻ってきたとき・残り時間が 0 になったときは、すぐ最新の状態を取りにいく
- リプレイで、参加者が作ったアバターが出ていなかったのを修正

## CPU の席に、情報工学科の先生

- 空いた席には、8 人の先生がランダムに座ります（高橋先生は柴犬推しのため登場しません）（同じ村に同じ先生は出ない）。イラストは、いただいた一枚絵から一人ずつ切り出し、名前の文字を消して使っています。
- プロフィールは、大学の教員紹介・researchmap などで公開されている専門分野と経歴をもとに書きました（悪口なし）。1 日目のあいさつは、それぞれの専門にちなんだものです。ゲームの判断はふつうの CPU と同じです。
- 円卓で先生の席にマウスをのせると、全身のイラストとプロフィール。リプレイの最初の紹介でも全身で出ます。先生の画面・分析ページにも同じ絵が出ます。

## 先生の画面

- 受付の画面に **QR コード**（押すと全画面）。人間モード／AIモードは切りかえ式にして、リンクは 1 つだけ表示
- 時間の設定は「時間をかえる」の中へ（ふつうは名前を入れて押すだけ）
- いまが「受付 → 試合 → 結果発表」のどこかを上に表示
- AIサバイバル戦のボタンは、AIモードの学生が 2 人以上いるときだけ表示

## 確認したこと

- 画面の通しテスト: 先生 1 + ブラウザの学生（人間・AI）+ 擬似学生で、エントリー → 試合 → 結果発表 → もう一回
- 画面サイズ: 1920×1080 / 1440×900 / 1366×768 / 1280×720 / 1024×768 / 390×800（スマホ）
- AIサバイバル戦（決勝・優勝まで）、自由ロビー、観戦、リプレイ（シーク・速さ変更）
- 通信断・異常な返事・再読み込み（`test/ui_stability.py`）
- QR コード: 参照実装（Python の qrcode）と全バージョンで一致することを確認

確認は、付属のモックサーバー（`test/gas_mock_server.js`）とダミー LLM で行いました。**本物の Apps Script・実機のスマホ・40 人規模の同時接続では試していません。** 授業の前に、先生の画面と学生の画面 2〜3 台で 1 試合まわしておくと安心です。
